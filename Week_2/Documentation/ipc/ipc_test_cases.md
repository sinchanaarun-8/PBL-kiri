# IPC Test Cases

## 1. Objective

To verify the functionality of the Core modules and the communication between the UI, Core, and Logger processes using POSIX Message Queues.

The testing covers:

- CPU operations
- Memory operations
- Stack operations
- Queue operations
- UI-to-Core communication
- Core-to-UI communication
- Core-to-Logger communication
- Log file generation
- Process termination

> **Note:** Core functional test cases below are documented as implemented test scenarios. The integrated IPC execution results are marked PASS only for operations that were actually verified during the demonstrated integrated run.

## 13. Testing Limitations

The CPU, Memory, Stack, and Queue operations are implemented in the Core and are documented as functional test scenarios.

However, the demonstrated integrated execution did not separately record observed PASS results for every individual CPU, Memory, Stack, and Queue operation.

Therefore, those operations are intentionally marked **Implemented** rather than falsely marked **PASS**.

The following operations require separate execution if individual PASS evidence is required:

- ADD
- SUB
- MUL
- DIV
- DIVIDE BY ZERO
- STORE
- READ
- PUSH
- POP
- PEEK
- ENQUEUE
- DEQUEUE
- QPEEK
- RESET
- Invalid command handling

---

## 14. Conclusion

The implemented Core modules provide CPU, Memory, Stack, and Queue functionality required by the simulator.

The verified integrated execution confirms successful communication through POSIX Message Queues between:

```text
UI → Core
Core → UI
Core → Logger
Logger → simulator.log
```

The integrated simulator successfully processed LOAD, RUN, STOP, and EXIT commands. The Core and Logger processes also terminated successfully.

The IPC architecture is therefore functioning correctly for the demonstrated multi-process execution.
